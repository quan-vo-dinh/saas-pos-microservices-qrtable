## 2. Kết quả zoom-out ở mức actor/domain/use case

Ở mức Chương 4, QRTable nên được trình bày như một hệ thống có bốn lớp kiến trúc chính:

1. Client layer: `customer-pwa`, `management-app`, `keycloak-theme`.
2. Edge/BFF layer: `apps/bff` làm HTTP API gateway, WebSocket gateway, guard chain và TCP/gRPC client.
3. Domain service layer: Authorizer, User-Access, SaaS, Catalog, Order, Kitchen, Payment.
4. Infrastructure layer: PostgreSQL, MongoDB, Redis, Kafka, Keycloak, SePay/VietQR, Cloudinary và Docker stack.

Khi nói theo actor/use case, các boundary kiến trúc cần giữ như sau:

## 12. Kết luận Phase 4A

Architecture evidence hiện tại đã được chuyển thành Chương 4 ở mức bản nháp có thể build được. Claim mạnh nhất nên giữ trong Chương 4 là: Nx monorepo, BFF single entry, database-per-service + `tenant_id`, service/data ownership, selective TCP/gRPC/Kafka/WebSocket, Redis access policy, Kafka 5-topic registry, dual auth model và two-tier payment architecture.
