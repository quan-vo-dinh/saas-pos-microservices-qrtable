# Step 2.5 Batch 6 QR Demo And Dynamic Tenant Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a final Step 2.5 batch that makes Management App QR codes
scannable, resolves tenant slug dynamically in Customer PWA, revokes old QR
tokens on regenerate, and makes repeated scans join the same active table
session.

**Architecture:** BFF adds public/current tenant metadata endpoints backed by
SaaS TCP. Catalog changes QR tokens from deterministic HMAC to stored opaque
random tokens. Order join-session becomes table-session idempotent. Management
App renders derived QR images client-side with `qrcode.react`; Customer PWA
resolves tenant slug before QR validation and session join.

**Tech Stack:** NestJS, Nx, TypeORM, TCP microservices, React Query,
Next.js/React, `qrcode.react`, existing BFF `ResponseDto`, existing tenant
headers/session headers.


  ```ts

  }
  ```

- [ ] **Step 2: Keep public resolver unauthenticated**

  Do not add `@Authorization` or `@Permissions` to the public resolver.

- [ ] **Step 3: Add current tenant endpoint**

  Add `@Controller('admin/tenant')` with:

  ```txt
  GET /admin/tenant/current
  ```

  It uses:

  ```ts

  @Permissions([PERMISSION.CATALOG_GET_LIST])
  ```

  It reads `tenantId` from `req[MetadataKey.TENANT_ID]`, sends
  `TCP_REQUEST_MESSAGE.SAAS.GET_BY_ID` only when the value is UUID-shaped. For
  legacy string tenant keys, send `TCP_REQUEST_MESSAGE.SAAS.GET_BY_SLUG`
  instead. Return
  `{ id, slug, name, isActive }`.

  `023772bb-391b-401c-936a-ed7034b69cec` và slug công khai `pho-viet`. Backend
  có thể giữ phủ resolver legacy `tenant_a` chỉ để tương thích, không coi là


## Completion Criteria

- `GET /public/tenants/:slug` resolves tenant slug to public tenant metadata.
- `GET /admin/tenant/current` gives Management App a backend source for tenant
  slug.
- Management App table QR dialog renders real scannable QR.
- Customer PWA no longer depends on `VITE_TENANT_ID` when QR URL contains
  `tenant`.
- QR regenerate invalidates old QR URLs.
- Repeated scans of an occupied table join the same active Order session.
- No QR image files are persisted in DB or Cloudinary.
