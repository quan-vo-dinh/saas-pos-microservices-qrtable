# Step 2.5 Batch 7 POS Tables Real Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Management App `/pos/tables` mock table map/detail data
with real Catalog table APIs and existing Step 2.5 POS order APIs, while keeping
payment/session-close/KDS work out of scope.

**Architecture:** `/pos/tables` should read table state from the existing
Catalog-backed `useTablesQuery()` and read active orders by table from the
existing admin order API. UI-only selected table state moves out of
`mocks/store` into a focused POS table UI store. Real table transfer is enabled
only when the selected table has a backend `sessionId`; cleaning status updates
use the existing Catalog table status mutation.

**Tech Stack:** Next.js App Router, React, Zustand, TanStack Query, existing
Management App authenticated API client, existing Catalog table service/hooks,
existing Order service/hooks, shadcn/Radix UI components.

## Scope Decision

### In Scope

- `/pos/tables` table grid/list reads real `RestaurantTable[]` from
  `useTablesQuery()`.
- `/pos/tables` table selection no longer depends on `apps/management-app/src/mocks/store.ts`.
- Table detail header/status/capacity/session reads real table data.
- Table detail active order summary reads real `useOrdersQuery({ tableId })`.
- Table transfer passes real `fromTableId` and `sessionId` when present.
- Mark-clean action uses existing `useUpdateTableStatusMutation()` to set table
  status to `available`.
- Loading/error/empty states are explicit and do not fall back to mock data.

### Out Of Scope

- `/pos/bills` and `CashBillPanel`: remain mock until Phase 3 Payment.
- `/pos/payment`: remains Phase 3 placeholder.
- Full running bill/payment close-session flow.
- Customer presence/timeline realtime for each table.
- KDS real backend integration.
- New backend endpoint for table active-session timeline.
- New analytics endpoints for mini charts/KPI history.
- Automatic mock fallback when API is unavailable.
