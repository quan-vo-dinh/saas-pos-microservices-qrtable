# Step 2.6 Kitchen Service + WebSocket Gateway Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Phase 2B Step 2.6: Redis-only Kitchen Service, SLA worker, KDS REST contract, and hardened BFF WebSocket Gateway for restaurant kitchen/bar realtime operations.

**Architecture:** Order Service remains the durable source of truth for customer-visible order state. Kitchen Service owns Redis-only KDS ticket/queue state, consumes Kafka `order.confirmed`, publishes internal Redis Pub/Sub queue-change hints after Redis mutation succeeds, and emits Kafka `kitchen.sla_warning` from a worker. BFF remains the HTTP/RBAC and WebSocket boundary, calling Kitchen over TCP and emitting Socket.IO events only as realtime hints; clients must refetch snapshots after reconnect or queue-change hints.

**Tech Stack:** Nx, NestJS 11, Nest TCP microservices, Kafka via `kafkajs`, Redis via `ioredis` for Kitchen state, Socket.IO with `@socket.io/redis-adapter` + `redis` package for multi-instance BFF broadcasting, Jest.

## Decisions Carried Forward

- Use audit recommendation Q1 Option B: Kitchen writes Redis first, then publishes internal Redis Pub/Sub `kds.queue_changed`; BFF must not emit KDS queue changes directly from `order.confirmed`.
- Use audit recommendation Q2 Option A: SLA uses Redis Sorted Set `kds:sla:due` plus a Kitchen worker.
- Remove batching completely. Do not create backend batch keys, batch DTO fields, batch events, `prepSignature`, or cross-order grouped quantities.
- Use audit recommendation Q4 Option A: Redis rebuild comes from Order Service active-order snapshots.
- Use audit recommendation Q5 Option A: add `PERMISSION.KITCHEN_SET_PRIORITY = 'kitchen.set_priority'` for OWNER/MANAGER/SUPER_ADMIN only.
- Scaffold Kitchen manually from the current `apps/order` pattern. A local `npx nx g @nx/nest:application --help` check hung on Nx daemon, so implementation should avoid generator dependence unless the daemon is reset and verified first.
- Do not commit per task during automated execution unless the repository owner explicitly asks for commits. Keep task checkpoints testable and leave final staging/commit to the owner.

Use Context7 Socket.IO/Nest pattern with `redis` package:

```ts
import { IoAdapter } from '@nestjs/platform-socket.io';
import { createAdapter } from '@socket.io/redis-adapter';
import { createClient } from 'redis';
import type { ServerOptions } from 'socket.io';

export class RedisIoAdapter extends IoAdapter {
  private adapterConstructor?: ReturnType<typeof createAdapter>;

  async connectToRedis(url: string): Promise<void> {
    const pubClient = createClient({ url });
    const subClient = pubClient.duplicate();
    await Promise.all([pubClient.connect(), subClient.connect()]);
    this.adapterConstructor = createAdapter(pubClient, subClient);
  }

  createIOServer(port: number, options?: ServerOptions): unknown {
    const server = super.createIOServer(port, options);
    if (this.adapterConstructor) {
      server.adapter(this.adapterConstructor);
    }
    return server;
  }
}
```
