# Step 2.2 — Mock UI (Cart / POS / KDS) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build complete mock UI for Customer PWA (Cart + Ordering + Tracking + Service Requests), Staff POS (Live Orders + Tables + Service Request Inbox + Cash Bills), and KDS (Kitchen + Bar stations) per `docs/ui-blueprint-step-2.2.md`, backed by fake-realtime events that match shared-types contracts, so Step 2.5 integration only swaps the data source.

**Architecture:**

- **PWA** (`apps/customer-pwa`, Vite + React Router v7, Tailwind v4): editorial-warm theme, cart drawer (`vaul`), `useCart` (existing Context) extended with `version`, order tracking timeline, service-request drawer. State: Context + TanStack Query. Mock data via Zustand + `@faker-js/faker` + `useFakeRealtime`.
- **Management App** (`apps/management-app`, Next.js 16 App Router, Tailwind v4): dashboard-dense POS theme on `(pos)` route group; industrial-contrast theme on `(kds)` route group. Existing role-routing middleware already gates access. State: Zustand stores per surface + TanStack Query for future swap.
- **Shared types unchanged.** `KDSTicket.station` extended **only in mock layer** as `KDSTicketMock = KDSTicket & { station: 'KITCHEN' | 'BAR' }`.
- **Fake realtime** emits events whose shapes match `libs/shared/types/src/lib/realtime-events.types.ts` 1:1 so Step 2.5 swap is a source change, not a payload change.

**Tech Stack:**

- UI: `@einvoice/frontend-ui` (existing lib) + local `src/components/ui/` for overrides, Radix primitives, `lucide-react`, `sonner` (toasts), `vaul` (drawers), **`framer-motion`** (install), **`@dnd-kit/core` + `@dnd-kit/sortable`** (install, KDS DnD), **`recharts`** (install, POS mini charts), **`@faker-js/faker`** (install, devDep).
- Forms: `react-hook-form` + `zod` (already in management-app; add to customer-pwa).
- State: Zustand (management-app has it; add to customer-pwa for mock store).
- Fonts: system + existing Inter; no new web fonts (per ADR).
- Audio: Web Audio API synthesized beeps (no mp3 assets).
- Mock data: `@faker-js/faker` seeded 42, deterministic fixtures.

**Icon stack (agent MUST — đồng bộ `docs/ui-blueprint-step-2.2.md` §5.6):**

- **Primary:** `lucide-react` — named imports only; icons are inline SVG components (`size`, `color`, `strokeWidth`, SVG props per [Lucide](https://lucide.dev/guide/packages/lucide-react)). Decorative by default — add **`aria-label`** when an icon is the sole indicator (notes column, icon-only buttons).
- **Reuse first:** `@einvoice/frontend-ui` if it already exports the same affordance with Lucide/shadcn patterns.
- **Do not:** use Unicode emoji (🍳⏱🟢🔴👥…) as UI icons, status dots, or avatars in JSX/static copy. Wireframe emoji in this plan = **concept only** → implement with Lucide from the blueprint mapping table.
- **Optional later (ADR):** `@tabler/icons-react`, `@phosphor-icons/react` if a glyph is truly missing from Lucide. Avoid `@mui/icons-material` alongside shadcn outline unless the surface switches to Material.

**Git workflow:** Work directly on `main`. Do NOT create commits — leave changes staged/unstaged for the user to review and commit. No per-task commit steps below.

**Out of scope (deferred):**

- Real backend integration (Step 2.5).
- `libs/shared/ui-tokens` Nx lib (Step 2.5 per blueprint §1).
- `MenuItem.station` in Catalog Service and `Order.priority`, `OrderItem.servedAt` in shared types (Step 2.4 tech-debt log in blueprint §0).
- Actual WebSocket wiring (mock only).
- Shared cart persistence across devices (mock single-device + faker-generated presence).

## Task 4: Fake realtime hook — management-app

**Files:**

- Create: `apps/management-app/src/mocks/use-fake-realtime.ts`

- [ ] **Step 1: Implement hook**

Behavior:

- On mount start 3 intervals:
  - Every 25–40s: generate `OrderCreatedEvent` (shape from `realtime-events.types.ts`), append to `liveOrders` with status `PENDING`, push notification, play `bell`.
  - Every 50–90s: generate `ServiceRequestedEvent`, append to `serviceRequests`.
  - Every 10s: for each `PROCESSING` order, with 25% probability emit `OrderStatusChangedEvent` (PROCESSING → READY), update store, play `tap`.
- Cleanup clears intervals on unmount.
- Return `{ lastEvent, pause, resume }`.
