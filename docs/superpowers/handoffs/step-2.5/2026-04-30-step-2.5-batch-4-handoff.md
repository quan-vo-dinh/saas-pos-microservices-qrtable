## Implementation Constraints

- Use `authApiClient`; do not create a second authenticated HTTP client.
- Preserve `Authorization` and `x-tenant-id` behavior from existing management
  API patterns.
- Polling is the functional baseline. Staff WebSocket hints belong to Batch 5.
- Do not wire KDS to real backend in this batch.
- Do not implement payment/cash confirmation.
- Do not add frontend permission logic beyond existing route/sidebar role UX;
  BFF remains permission source of truth.
