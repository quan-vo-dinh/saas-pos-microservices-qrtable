| Active snapshots | Return tenant-scoped active Order snapshots for Redis rebuild.                                                |
| Mark items ready | Mark KDS ticket item IDs as Order item `READY`; move order to `READY` when all active items ready.            |

| Transfer data    | Ensure table transfer response contains data BFF needs to patch Kitchen snapshots.                            |
| Tests            | Cover tenant filtering, active-state filtering, readiness transitions, revert transitions, and transfer data. |

## Implementation Constraints

- Every DB query must filter by `tenant_id`.
- Do not query Kitchen Redis from Order.
- Do not change `order.confirmed` producer payload unless a test proves the
  current payload violates Step 2.6 spec.
- `KDS_ACTIVE_ORDERS_GET` should return active confirmed orders only:
  `PROCESSING` and `READY`; exclude `PENDING`, `CANCELED`, `SERVED`,
  `COMPLETED`.
- Rebuild snapshots must include station-bearing items.
- `MARK_ITEMS_READY` and `REVERT_ITEMS_PROCESSING` must be idempotent by current
  DB state where no durable command log exists.
- Do not emit WebSocket events from Order Service.
- Do not add batching.
