| ---------------- | ------------------------------------------------------------------------------------------------------ |
| Kafka producer   | Produce `KitchenSlaWarningEvent` to `kitchen.sla_warning` with key `tenantId`.                         |

| Cleanup hooks    | Keep retention/dead member cleanup minimal and aligned with existing ticket fields.                    |
| Tests            | Cover warning, breach, dedupe, skip logic, Kafka payload, rebuild lock, and recovered ticket behavior. |

## Implementation Constraints

- Use `kitchen.sla_warning`, not `kitchen.sla_warn`.
- SLA trigger must be worker-driven, not request-driven and not Redis keyspace
  notification driven.
- Dedupe SLA by `kds:{tid}:dedupe:sla:{ticketId}:{level}:{bucket}`.
- Skip tickets in `READY`, `VOIDED`, or `ARCHIVED`.
- Recovery rebuild uses Order Service active snapshots and cannot restore
  already-started prep state; recovered tickets start as `PENDING`.
- Do not replay Kafka as the recovery mechanism.
- Do not add a Kitchen database.
- Do not add batching.
