## Batch Tasks

| Deliverable    | Required result                                                                                          |
| -------------- | -------------------------------------------------------------------------------------------------------- |
| KDS REST       | Add guarded `/admin/kds` queue/start/done/recall/priority endpoints.                                     |
| Station access | Enforce CHEF=KITCHEN, BARISTA=BAR, OWNER/MANAGER/SUPER_ADMIN=both.                                       |
| Ready sequence | BFF calls Kitchen `MARK_READY`, then Order `MARK_ITEMS_READY`, then emits ready/order events.            |
| Compensation   | If Order readiness fails, BFF recalls Kitchen ticket and emits no customer ready event.                  |
| Transfer patch | After successful table transfer, BFF calls Kitchen `PATCH_TABLE_SNAPSHOT`.                               |
| Void flow      | After processing cancellation, BFF calls Kitchen `VOID_BY_ORDER`.                                        |
| Redis adapter  | Register Socket.IO Redis adapter before app listens.                                                     |
| WS auth        | Validate staff JWT and customer session in handshake; do not mint sessions.                              |
| WS rooms       | Server-derived rooms; client `join.staff`/`join.session` cannot assign rooms.                            |
| Bridges        | Subscribe to `realtime:kds:*`; consume `kitchen.sla_warning`; emit WS hints.                             |
| Tests          | Cover REST permissions, station restrictions, compensation, room assignment, subscriber, and SLA bridge. |

## Implementation Constraints

- Staff REST endpoints must use `@Authorization({ secured: true })` and
  `@Permissions(...)`.
- Use `KITCHEN_SET_PRIORITY` for priority endpoint.
- Do not trust client-supplied room IDs.
- Customer WebSocket handshake validates existing session; it must not create a
  new session.
- BFF must not emit KDS queue change from `order.confirmed`.
- Redis Pub/Sub channel is `realtime:kds:{tenantId}` and subscription pattern is
  `realtime:kds:*`.
- Socket.IO Redis adapter does not provide replay; reconnect behavior remains
  client refetch in Batch 6.
- If long polling remains enabled, document sticky session caveat or configure
  WebSocket-only clients where applicable.
- Do not add batching.
