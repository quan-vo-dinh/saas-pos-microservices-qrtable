## Implementation Constraints

- Customer cancel only applies to own-session `PENDING` orders.
- Processing cancel requires manager/owner command path and a reason.
- Processing cancel must call Catalog `STOCK_RELEASE_FOR_ORDER`.
- `REQUEST_BILL` service request routes to `BillService.requestBill`.
- Bill request requires active session, open bill, empty cart, and all active
  orders served.
- Bill request locks cart and sets Catalog table status to `billing`.
- Transfer must use Redis locks for session, source table, and destination
  table before DB/table status changes.
- Transfer keeps the same session ID and cart key.
- Every method remains tenant-scoped.
