## Implementation Rules

- Work on `main`.
- Do not commit.
- Do not implement BFF REST/WebSocket in this batch.
- Customer cancel only applies to own-session `PENDING` orders.
- Processing cancel requires privileged staff command path and a reason.
- Processing cancel must call Catalog `STOCK_RELEASE_FOR_ORDER`.
- `REQUEST_BILL` service request routes to `BillService.requestBill`.
- Bill request requires active session, open bill, empty cart, and all active
  orders served.
- Bill request locks cart and sets table status to `billing` through Catalog.
- Transfer uses Redis locks for session/source/destination before mutations.
- Transfer keeps the same session ID and cart key.
- Every method must remain tenant-scoped.
