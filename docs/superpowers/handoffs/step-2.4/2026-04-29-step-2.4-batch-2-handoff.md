## Implementation Constraints

- Use Catalog's existing module structure:
  `controllers/`, `services/`, `repositories/`, `tests/`.
- Every Catalog query/mutation must include `tenantId`.
- Order Service must later call these TCP commands; it must not query or update
  `menu_items` directly.
- Stock deduction must run in a Catalog transaction with pessimistic locking or
  equivalent safe update semantics.
- The stock commands should be idempotency-aware where the plan specifies an
  idempotency key; if full durable idempotency is too large, document the gap
  explicitly before continuing.
