## Implementation Constraints

- Submit must be idempotent by `tenantId + sessionId + idempotencyKey`.
- Submit creates `PENDING` order and first `OPEN` bill inside one Order DB
  transaction.
- Submit must not deduct stock.
- Confirm must lock the order row and only allow `PENDING -> PROCESSING`.
- Confirm must call Catalog `STOCK_DEDUCT_FOR_ORDER`.
- On Catalog stock failure, local Order transaction must roll back.
- Kafka outbox row is written in the same transaction as confirmation.
- Outbox publishes `order.confirmed` with partition key `tenantId`.
- BFF Kafka consumer bridge remains out of scope.
