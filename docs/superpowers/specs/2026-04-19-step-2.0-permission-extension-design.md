## 1. Problem Statement

Phase 1 đã hoàn thành Catalog domain với 6 roles (`SUPER_ADMIN`, `OWNER`, `MANAGER`, `WAITER`, `CHEF`, `BARISTA`) và 6 permission domains (`SAAS`, `CATALOG`, `INVOICE`, `USER`, `ROLE`, `PRODUCT`). Phase 2A sắp triển khai Order Service, Kitchen state machine, Payment cash flow, Table operations, và Service Request — **mỗi domain mới phải có permission enum và role-mapping rõ ràng TRƯỚC khi BFF/Order Service expose endpoint**, để tránh "lỗ hổng" RBAC khi tích hợp POS/KDS/PWA.

Step 2.0 là blocking prerequisite cho Steps 2.1–2.5 (và Phase 2B, Phase 3): không có permission enum + DB seed sẵn, các controller sau không thể áp `@Permissions(...)` decorator chính xác.

## 2. Goals

1. Bổ sung **20 permission values mới** cho 5 domain: `ORDER_`_, `KITCHEN\__`, `PAYMENT*\*`, `TABLE*_`, `SERVICE*REQUEST*_`.
2. Định nghĩa **canonical permission matrix** cho 6 roles, lưu tại `docs/architecture/permission-matrix.md` làm single source of truth.
3. Update `apps/user-access/src/seeder/role.json` khớp matrix.
4. Re-seed MongoDB để DB phản ánh enum/matrix mới.
5. Verify 3-layer (unit + JSON validation + integration script) không tạo permission drift.
6. Cleanup legacy enum (`ADMINISTRATOR`, `ACCOUNTANT`) và sync `docs/references/auth-system-reference.md`, `docs/phases/phase-2a-order-kafka.md`.

### 6.4 — Operational Strategy (Section B)

**Execution order (dependency-driven):**

```
1. Tạo doc permission-matrix.md (canonical)
        ↓
2. Mở rộng PERMISSION enum (+ xóa ADMINISTRATOR/ACCOUNTANT)
        ↓
3. Cập nhật role.json theo matrix
        ↓
4. Viết unit tests cho PermissionGuard + Layer 2 JSON validation test
        ↓
5. Viết integration test script
        ↓
6. Re-seed MongoDB (prune mode)
        ↓
7. Chạy integration test → verify pipeline
        ↓
8. Đồng bộ auth-system-reference.md + phase-2a-order-kafka.md
```

**Re-seed command:**

```bash
MONGODB_URI='mongodb://root:password@localhost:27017/?authSource=admin' \
MONGO_DB_NAME='qrtable' \
node tools/seed.js apps/user-access/src/seeder prune
```

**Why `prune` is safe:** `_id` cố định → re-insert đúng `_id` → `user.roles` references không bị orphan.

**Cache invalidation gotcha:** UserGuard cache `user-token:{sha256}` TTL 30 phút trong Redis. Sau seed, JWT cũ vẫn dùng cache cũ. **Solution: re-login** (token mới → cache key mới). Document trong `permission-matrix.md` §8 Operational Procedures.

**Roll-back:** `git checkout HEAD -- apps/user-access/src/seeder/role.json && node tools/seed.js apps/user-access/src/seeder prune`.

### 6.5 — Verification Strategy (Section C — 3 Layers)

**Layer 1 — PermissionGuard Unit Tests (extend existing file)**

File: `apps/bff/src/app/guards/permission.guard.spec.ts`

Mở rộng từ 4 test hiện có lên ~16 test. Pattern: parameterized `describe.each` cover matrix invariants. Bắt buộc include 2 acceptance scenarios theo phase-2a spec:

- WAITER với `ORDER_CONFIRM` → `canActivate` returns `true`
- CHEF với `PAYMENT_CONFIRM_CASH` → `canActivate` throws `BusinessException` (FORBIDDEN)

Plus ≥10 additional cases coverage cho mọi role × representative permission per domain.

Run: `npx nx test bff` (no DB/Keycloak required).

**Layer 2 — Role-JSON Schema Validation Test (NEW file)**

File: `apps/user-access/src/seeder/role.spec.ts`

Anti-drift firewall: load `role.json`, assert mỗi role có **exact** permissions per canonical matrix. Bất kỳ ai sửa role.json mà không update matrix → CI fail. Bất kỳ ai thêm permission mà quên seed → CI fail.

3 test cases:

1. Each of 6 roles has exactly the expected permission set
2. Every permission value in role.json exists in `PERMISSION` enum
3. Total roles count = 6, names match expected list

Run: `npx nx test user-access` (~50ms, no dependencies).

**Layer 3 — Integration Verification Script (NEW file)**

File: `tools/verify-permission-matrix.sh`

End-to-end verify: Keycloak login → BFF `/authorizer/me` → DB roles → permissions array. Chạy với pre-seeded user data (đã có sẵn từ `auth-bootstrap-users.json`).

Cho mỗi user (6 roles):

1. POST `/api/v1/authorizer/login` với username/password → lấy `accessToken`
2. GET `/api/v1/authorizer/me` với Bearer token → lấy `permissions` array
3. Assert positive permissions (must exist) và negative permissions (must NOT exist)

Run prerequisites:

- Stack chạy: `pnpm dev:bff-auth` (BFF + Authorizer + Mongo + Redis + Keycloak)
- DB seeded: `node tools/seed.js apps/user-access/src/seeder prune`
- Verify: `bash tools/verify-permission-matrix.sh`
