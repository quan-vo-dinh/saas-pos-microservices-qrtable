## 1. Problem Statement

QRTable Phase 2A sắp triển khai 3 layers song song:

- **Step 2.2** rebuilds POS + KDS mock UI
- **Step 2.4** xây Order Service backend (PostgreSQL + Redis + Kafka producer)
- **Step 2.5** wires FE ↔ BE qua BFF Direct (`order.created`, `service.requested`) + REST endpoints

Cả 3 layers cần **single source of truth** cho:

- Domain entities (`Order`, `OrderItem`, `Bill`, `Session`, `CartItem`, `ServiceRequest`)
- Status enums (`OrderStatus`, `OrderItemStatus`, `BillStatus`, `SessionStatus`, `ServiceRequestType`, `ServiceRequestStatus`, `PaymentMethod`)
- Realtime event payloads (BFF Direct WebSocket + Kafka topic `order.confirmed`)
- State transition matrices (định nghĩa allowed transitions cho 3 state machines)

**Existing state có 2 vấn đề lớn:**

1. **Type drift đã bắt đầu**: `libs/shared/types/src/lib/order.types.ts` hiện có:

   ```typescript
   export type OrderStatus = 'pending' | 'confirmed' | 'preparing' | 'ready' | 'served' | 'cancelled';
   ```

   KHÔNG khớp phase doc spec yêu cầu `DRAFT → PENDING → PROCESSING → READY → SERVED → COMPLETED → CANCELED` (UPPERCASE, 7 values, semantics khác).

2. **Missing types**: Phase doc spec list 6 entities + 2 enums, nhưng implementation cần thêm 4 status enums (Bill, Session, ServiceRequest, OrderItem), 1 thêm event type (`ServiceRequestedEvent` cho BFF Direct emit `service.requested`), và 1 Kafka payload type (`OrderConfirmedEvent`). Không define ở Step 2.3 → mỗi service tự define → cross-service drift.

Step 2.3 là **foundation lock**: trước khi Step 2.2 build mock UI và Step 2.4 build BE, contract phải đóng băng. Bất kỳ service hay UI nào sau này import từ `@einvoice/types` đều thấy cùng shape.

**Convention defaults confirmed (write thẳng vào spec, không ask separately):**

- Money type: `number` đại diện VND integer (no decimals) — match existing
- Date type: ISO 8601 `string` — match existing
- ID type: `string` (UUID v4 hoặc Mongo ObjectId hex string)
- Cart `version`: `number` (incrementing integer for optimistic locking)
- `idempotencyKey`: `string` (UUID v4, FE generates)
- `tenantId`: `string` (no branded type)
- Casing enum values: UPPERCASE (`DRAFT`, `PENDING`, `PROCESSING`, etc.)

### 5.3 Status mapping (breaking change)

| Old (lowercase string) | New (UPPERCASE enum)     | Note                                                          |
| ---------------------- | ------------------------ | ------------------------------------------------------------- |
| `'pending'`            | `OrderStatus.PENDING`    | Đổi case                                                      |
| `'confirmed'`          | `OrderStatus.PROCESSING` | **Semantic shift** — confirmed nay là processing (đã vào bếp) |
| `'preparing'`          | `OrderStatus.PROCESSING` | **Consolidated** — confirmed + preparing gộp 1 status         |
| `'ready'`              | `OrderStatus.READY`      | Đổi case                                                      |
| `'served'`             | `OrderStatus.SERVED`     | Đổi case                                                      |
| `'cancelled'`          | `OrderStatus.CANCELED`   | Đổi case + spelling (US per phase doc)                        |
| (chưa có)              | `OrderStatus.DRAFT`      | NEW — cart chưa submit (status implicit cho cart aggregate)   |
| (chưa có)              | `OrderStatus.COMPLETED`  | NEW — sau bill paid                                           |

**Lý do consolidate `confirmed` + `preparing`:**

- Old flow: `pending` (chờ staff) → `confirmed` (staff ok) → `preparing` (bếp làm)
- New flow: `DRAFT` (cart) → `PENDING` (gửi → chờ staff confirm) → **`PROCESSING`** (confirm xong + bếp làm cùng nghĩa: đơn đang được xử lý)
- Phase doc spec không có `confirmed` độc lập — confirm action chỉ là transition trigger `PENDING → PROCESSING`, không phải status lưu lâu

#### 6.1.4 State transition matrices (3 matrices)

**File: `libs/shared/types/src/lib/order.types.ts`** (append after enum):

```typescript
/**
 * Allowed Order state transitions per Phase 2A spec §8.
 * Used by:
 *   - BE Order Service (Step 2.4): validate transition trước khi update DB
 *   - FE POS (Step 2.5): disable invalid action buttons
 *
 * @example
 *   if (!ALLOWED_ORDER_TRANSITIONS[currentStatus].includes(targetStatus)) {
 *     throw new InvalidOrderTransitionException(currentStatus, targetStatus);
 *   }
 */
```

## Appendix A — Convention Reference Quick Card

| Element                   | Convention                                    | Example                             |
| ------------------------- | --------------------------------------------- | ----------------------------------- |
| Type construct (entities) | `type` alias                                  | `export type Order = { ... }`       |
| Type construct (enums)    | TS `enum`                                     | `export enum OrderStatus { ... }`   |
| Naming (entities)         | PascalCase, NO I-prefix                       | `Order`, `Bill`, `Session`          |
| Naming (enum values)      | UPPERCASE_SNAKE_CASE                          | `PENDING`, `PENDING_PAYMENT`        |
| Field naming              | camelCase                                     | `tableId`, `idempotencyKey`         |
| Money type                | `number` (VND integer)                        | `totalAmount: 195000`               |
| Date type                 | ISO 8601 `string`                             | `createdAt: '2026-04-06T10:30:00Z'` |
| ID type                   | `string`                                      | `id: 'order-001'`                   |
| Optional fields           | `field?: T` (TypeScript optional)             | `note?: string`                     |
| Denormalization           | Always include `*Name` for display            | `tableName`, `menuItemName`         |
| Transition matrices       | `const` object, `as const` for type narrowing | `ALLOWED_ORDER_TRANSITIONS`         |
